# 웹툰 대사 편집 — 슬롯을 채우고 말투를 지킨다

패널이 선언한 말풍선 슬롯에 대사를 채우고, 화자별 말투와 분량 예산을 지킨다.

## 웹툰 대사의 제약

소설 대사와 다른 점은 **공간이 유한하고, 그림이 이미 절반을 말하고 있다**는 것이다.

- 말풍선은 그림을 가린다 → 그림이 이미 보여주는 것을 대사로 반복하면 정보는 안 늘고 그림만 가려진다
- 컷당 체류 시간이 짧다 → 한 말풍선을 두 번 읽게 만들면 독자는 그냥 넘긴다
- 스크롤은 되돌아가지 않는다 → 앞 컷을 기억해야 이해되는 대사는 실패한다
- 슬롯은 이미 정해져 있다 → 대사가 길어서 슬롯을 늘려야 한다면, 그건 대사를 줄여야 한다는 신호다

## 워크플로우

### 1. 입력 확보

Read 대상:
- `_workspace/01_style_bible.md` — `SB-TEXT-*`(화법·글자수 규칙), 화자별 말투 지문, `SB-NEVER-*`
- `_workspace/02_story_beatsheet.md` — 각 비트의 정보 공개 계획
- `_workspace/04_panel_layout.json` — 슬롯 목록과 `max_chars` 예산
- `_workspace/03_character_sheet.json` — 화자 이름 표기

스키마는 `webtoon-panel-layout/references/panel-schema.md`의 2절을 Read한다.

### 2. 슬롯 예산 확인

작성 전에 슬롯별 `max_chars`와 패널별 총량을 먼저 파악한다. 쓰고 나서 줄이면 정보가 아니라 뉘앙스가 잘려나가 대사가 딱딱해진다.

패널 총 글자수는 `height / 8`을 넘지 않는 것이 기준이다. 예산이 명백히 부족하면 임의로 슬롯을 추가하지 말고 리뷰에서 panel-planner에게 요청한다 — 슬롯 신설은 패널의 권한이다.

### 3. 화자별 말투 유지

말투는 어미·1인칭·어휘 세 축으로 고정한다. `SB-TEXT-*`의 화자별 지문이 정본이며, 지문에 없는 화자가 등장하면 지문을 먼저 요청한다.

말투 붕괴가 실제로 일어나는 지점:
- **감정이 격해질 때** — 화난 인물은 누구나 비슷하게 말하게 되기 쉽다. 격앙 상태에서도 어미와 1인칭은 유지한다
- **설명해야 할 때** — 정보를 전달하려다 화자 전원이 같은 서술체가 된다
- **분량을 줄일 때** — 압축하면서 어미가 잘려 말투가 사라진다

### 4. 설명 대사 제거

웹툰에서 가장 흔한 결함이다. 다음은 전부 삭제 또는 그림으로 이관한다:

| 유형 | 예 | 처리 |
|------|-----|------|
| 그림 반복 | (비 오는 컷에서) "비가 오네" | 삭제. 그림이 이미 말했다 |
| 자기 상태 낭독 | "나는 지금 화가 났다" | 표정·SFX로 이관 |
| 독자용 설명 | "3년 전 사고 이후로 우리는…" | 필요하면 내레이션 1개로 압축, 아니면 다음 회차로 미룸 |
| 이름 부르기 남발 | 매 대사마다 상대 이름 호명 | 첫 등장 시 1회만 |

**정보를 지운 것이 아니라 옮긴 것인지 확인한다.** 삭제한 정보가 어디에도 없으면 독자가 이해하지 못한다. 그림·표정·SFX·다음 컷 중 어디로 갔는지 `note` 필드에 남긴다.

### 5. 말풍선 타입 선택

| 타입 | 쓰는 곳 | 주의 |
|------|--------|------|
| `normal` | 기본 발화 | |
| `thought` | 속마음 | 남발하면 서스펜스가 죽는다. 회차당 소수로 |
| `shout` | 고함·비명 | 짧아야 한다. 20자 넘으면 고함으로 안 읽힌다 |
| `whisper` | 속삭임·기어드는 말 | 폰트가 작아지므로 15자 이내 |
| `narration` | 화자 밖 서술 | 시제를 회차 내내 통일한다 |
| `caption` | 시간·장소 자막 | "3년 후" 같은 최소 정보만 |

슬롯이 선언한 `type`과 다른 타입을 쓰려면 리뷰에서 요청한다. 임의 변경은 정합성 검증에서 MAJOR로 잡힌다.

### 6. 효과음(SFX)

SFX는 `04_panel_layout.json`의 `sfx` 배열에 있고 대사 스크립트에는 넣지 않는다. 표기가 어색하면 리뷰로 지적한다.

한국어 SFX 원칙: 의성어는 실제 소리에 가깝게(`쿵` vs `쾅`은 다른 무게), 감정 표현 의태어는 남용 금지. 외국어 SFX 음차(`뚜둥`, `두근`)는 작품 톤에 따라 바이블에서 정한다.

### 7. 산출물

`_workspace/05_dialogue_script.json`에 쓴다. `char_count`는 반드시 `len(text)`와 일치시킨다 — 불일치는 텍스트를 고치고 갱신을 빠뜨린 흔적이라, 다른 곳도 갱신 누락됐다는 신호다.

작성 후 반드시 정합성 검증을 돌린다:

```bash
python3 webtoon-studio/.claude/skills/webtoon-style-consistency/scripts/validate_package.py \
  --panels _workspace/04_panel_layout.json \
  --dialogue _workspace/05_dialogue_script.json \
  --characters _workspace/03_character_sheet.json
```

BLOCKER가 남은 상태로 제출하지 않는다. 참조가 깨진 스크립트는 리뷰어의 지적을 그 한 원인으로 수렴시켜 나머지 관점을 묻는다.

### 8. 자기 검수

- 선언된 모든 슬롯이 채워졌고, 선언되지 않은 슬롯에 쓰지 않았는가
- 각 화자의 어미·1인칭이 지문과 일치하는가
- 소리 내어 읽어 걸리는 문장이 없는가 — 웹툰 대사는 구어다
- 비트시트가 이 시점에 숨기기로 한 정보를 노출하지 않았는가
- `char_count`가 실제 길이와 같은가

## 다른 에이전트의 산출물을 리뷰할 때

렌즈는 **화법과 분량 수용력**이다.

주로 보는 것:
- 패널의 `max_chars` 예산으로는 그 비트의 정보를 전달할 수 없는 컷이 있는가 — 예산 부족은 대사가 아니라 컷 설계의 문제다
- 한 컷에 말풍선이 몰려 읽기 순서가 모호한가 (같은 컷 슬롯의 `Δy < 0.18`)
- 비트시트가 대사로만 전달 가능한 정보를 대사 슬롯 없는 컷에 배치했는가
- 말풍선 위치가 인물 얼굴을 가리는 좌표인가
- 비트의 화자 배분이 특정 인물에게 쏠려 다른 인물이 회차 내내 침묵하는가

지적은 `SB-TEXT-*` 또는 슬롯/비트 ID를 인용한다.

## 개정 요청을 받았을 때

`_workspace/07_consistency_report.md`의 "→ dialogue-editor" 섹션만 읽고 수정한다. 수정본은 `_workspace/08_r{N}_dialogue_script.json`에 저장하고, 저장 후 정합성 검증을 다시 돌린다.

분량 축소 지시를 받으면 어미부터 자르지 않는다. 어미가 말투를 지탱하므로, 줄일 때는 **수식어 → 중복 정보 → 문장 분할 → 어미** 순서로 손댄다.
