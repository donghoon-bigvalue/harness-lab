# 웹툰 패널 레이아웃 — 세로 스크롤 연출 설계

스토리 비트시트를 세로 스크롤 컷 시퀀스로 번역하고, 검수 가능한 콘티로 렌더링한다.

## 세로 스크롤의 전제

세로 웹툰은 페이지 만화와 근본이 다르다. 페이지 만화는 독자가 한 면을 통째로 보고 시선을 자유롭게 움직이지만, 세로 스크롤은 **독자가 화면 높이만큼의 창을 위에서 아래로 밀며 본다.** 따라서:

- 독자는 다음 컷을 미리 볼 수 없다 → **여백이 곧 시간**이다. 긴 여백은 침묵과 긴장을 만든다
- 시선은 단방향이다 → 컷마다 시선 착지점(`focus`)이 하나여야 한다. 두 개면 독자가 놓친다
- 컷 높이가 곧 체류 시간이다 → 중요한 컷을 크게가 아니라 **길게** 만든다
- 반전은 스크롤 경계에서 터진다 → 충격 컷 앞에는 긴 여백을 둬 화면 밖에 숨긴다

## 워크플로우

### 1. 입력 확보

`webtoon/_workspace/01_style_bible.md`의 `SB-RHYTHM-*`, `SB-TEXT-*`와 `webtoon/_workspace/02_story_beatsheet.md`를 Read한다. 바이블의 화당 컷 예산이 컷 분할의 상한이다.

데이터 스키마·ID 규칙·열거값은 `references/panel-schema.md`를 Read한다.

### 2. 컷 예산 배분

비트별로 컷 수를 먼저 배분한 뒤 개별 컷을 설계한다. 컷부터 그리면 도입부에 예산을 다 쓰고 클라이맥스가 빈약해진다.

기준 배분(전체 컷 예산 기준):

| 구간 | 비중 | 컷 성격 |
|------|------|--------|
| 도입 (훅) | 15% | 큰 컷 소수. 첫 3컷 안에 이 회차를 계속 볼 이유를 준다 |
| 전개 | 35% | 중간 크기 다수. 정보 전달 밀도가 높다 |
| 전환 | 15% | 리듬 변속. 짧은 컷 연타 또는 긴 정지 |
| 클라이맥스 | 25% | 최대 높이 컷. 회차에서 가장 긴 컷이 여기 있어야 한다 |
| 훅/여운 | 10% | 2~4컷. 마지막 컷은 다음 화를 열어야 한다 |

### 3. 컷 리듬 설계

같은 높이가 3컷 이상 연속하면 독자는 스크롤을 가속하고 내용을 흘린다. 높이를 **의도적으로 진동**시킨다.

| 연출 의도 | 패턴 |
|----------|------|
| 가속·긴박 | 짧은 컷(300~450px) 3~5개 연타, `gutter_after` 최소(16~24px) |
| 감속·여운 | 긴 컷(1200px+) 1개, 뒤에 넓은 여백(150~300px) |
| 충격 | 긴 여백(250px+) → 최대 높이 컷. 여백이 클수록 충격이 크다 |
| 대화 | 중간 컷(500~700px) 교대, 화자 전환마다 앵글 변경 |
| 시간 경과 | `transition: time-skip` + 여백 200px 이상 |

**클라이맥스 컷은 회차 최대 높이여야 한다.** 독자가 가장 오래 머무는 컷이 감정 정점과 일치하지 않으면 연출이 어긋난다.

### 4. 샷 사이즈 선택

샷은 정보량과 감정 거리를 동시에 정한다.

| 샷 | 쓰는 곳 | 주의 |
|----|--------|------|
| `establishing` | 장소·시간 전환 직후 | 회차당 2~3개면 충분. 남발하면 진행이 늘어진다 |
| `wide` | 인물 관계·동선 | 인물 표정이 안 보이므로 감정 씬에 쓰지 않는다 |
| `medium` | 대화 기본값 | 연속 사용 시 지루 — 앵글로 변화를 준다 |
| `closeup` | 감정 전환점 | 회차당 정점 몇 곳에만. 흔하면 정점이 평평해진다 |
| `extreme-closeup` | 결정적 디테일(눈·손·물건) | 직전 컷에서 그 대상을 미리 보여줘야 독자가 인식한다 |
| `insert` | 문자·사진·소품 단독 | 텍스트가 들어가면 가독 크기 확보 |

### 5. 말풍선 자리 배치

말풍선은 **자리만** 선언한다. 텍스트는 dialogue-editor의 정본이다. 여기서 텍스트까지 쓰면 이중 정본이 생겨 어느 쪽이 최신인지 알 수 없게 된다.

배치 원칙:
- 읽기 순서는 **위→아래**다. 좌우 배치로 순서를 표현하려 하면 세로 스크롤에서 무너진다. 같은 컷의 두 말풍선은 y좌표를 충분히 벌린다(`Δy ≥ 0.18`)
- 인물 얼굴을 가리지 않는다 — 표정이 대사보다 많은 정보를 나른다
- `max_chars`는 **공간 예산 통보**다. 컷 높이와 말풍선 개수에서 역산한다: 컷당 총 글자수 ≈ `height / 8`을 넘지 않게 잡는다
- 컷당 말풍선 4개가 상한이다. 초과하면 컷을 쪼갠다

### 6. 콘티 렌더링

숫자로만 된 레이아웃은 검수가 불가능하다. 실제 비율로 쌓아 봐야 리듬 단절·말풍선 충돌·과밀 컷이 드러난다.

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/skills/panel-layout/scripts/render_conti.py \
  --panels webtoon/_workspace/04_panel_layout.json \
  --dialogue webtoon/_workspace/05_dialogue_script.json \
  --out webtoon/_workspace/09_conti.html
```

> `${CLAUDE_PLUGIN_ROOT}`는 **셸 환경변수가 아니다.** 플러그인이 설치된 절대 경로로 직접 치환해서 실행한다 — 스킬을 호출하면 그 경로를 알 수 있다. 그대로 넘기면 `/skills/...`로 해석되어 파일을 찾지 못한다.

`--dialogue`는 선택이다. 생략하면 말풍선 자리에 화자·타입만 표시되므로, 대사 작성 전 단계에서도 리듬 검수가 가능하다. 출력은 외부 리소스가 없는 단일 HTML이라 브라우저로 바로 열람·공유된다.

**렌더 후 직접 확인할 것:** 총 높이가 바이블의 화당 분량에 맞는가 / 같은 높이가 3컷 이상 연속하는 구간이 있는가 / 말풍선이 컷 경계나 서로에 붙어 있는가 / 클라이맥스 컷이 실제로 가장 긴가.

### 7. 자기 검수

산출 직전 확인:
- 모든 `beat`가 최소 1개 컷에 매핑됐는가 (비트 누락 = 서사 구멍)
- 모든 등장 인물이 캐릭터 시트에 있는가
- 마지막 컷이 훅으로 끝나는가
- 컷 수가 바이블 예산의 ±15% 안인가

## 개정 요청을 받았을 때

`webtoon/_workspace/07_consistency_report.md`의 "→ panel-planner" 섹션만 읽고 수정한다. 수정본은 `webtoon/_workspace/08_r{N}_panel_layout.json`에 저장하고 원본은 남긴다 — 리듬 수정은 개악 여부 판단이 주관적이라 비교 대상이 필요하다.

**컷 하나를 고치면 앞뒤 리듬이 바뀐다.** 높이를 조정할 때는 인접 2컷의 리듬을 함께 확인하고, 조정 결과를 콘티로 다시 렌더해 확인한 뒤 제출한다.

리뷰 지적이 바이블 규칙과 충돌하면(예: 대사량 확보를 위해 컷을 키우라는 요구가 `SB-RHYTHM` 상한을 넘김) 임의로 따르지 말고 리포트에 이의를 기록한다. 중재는 style-guardian의 권한이다.
