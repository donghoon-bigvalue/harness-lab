# 웹툰 스타일 일관성 — 바이블 수립 · 교차 리뷰 · 중재

웹툰 에피소드의 4개 산출물(스토리·캐릭터·패널·대사)이 하나의 작품처럼 읽히도록 만드는 공유 기준 스킬. `webtoon-studio` 하네스의 전 에이전트가 이 스킬에 바인딩된다.

## 왜 바이블이 먼저인가

스타일 일관성은 사후 검수로 만들어지지 않는다. 네 명이 각자 만든 뒤 맞추면, 서로 다른 전제 위에 쌓인 산출물이라 수정이 연쇄한다 — 대사 톤을 바꾸면 컷 수용력이 깨지고, 캐릭터 앵커를 바꾸면 이미 확정한 클로즈업 컷이 무효가 된다.

따라서 순서는 **바이블 확정 → 병렬 제작 → 교차 리뷰 → 중재 → 개정**이다. 제작 전에 확정된 규칙이 많을수록 리뷰 라운드가 짧아진다.

## 1. 스타일 바이블 수립 / 갱신

작성 주체는 style-guardian 단독이다. 여러 에이전트가 바이블을 동시 편집하면 정본이 사라지기 때문이다.

**절차:**
1. 기존 바이블(`webtoon/series-bible.md` 또는 이전 회차 `webtoon/_workspace*/01_style_bible.md`)이 있으면 Read하여 승계한다. 신규 작품일 때만 처음부터 작성한다.
2. 사용자 입력(장르·톤·레퍼런스·캐릭터 설정)에서 규칙을 추출한다.
3. 사용자가 지정하지 않은 항목은 **장르 관례로 기본값을 채우되, 채웠다는 사실을 8절 미해결 쟁점에 남긴다.** 추정으로 채운 규칙을 확정 규칙처럼 제시하면, 나중에 사용자가 뒤집을 때 이미 그 위에 4개 산출물이 쌓여 있다.
4. 규칙 ID를 부여하고 검증 방법을 함께 적는다.

구조·ID 체계·작성 예시는 `references/style-bible-template.md`를 Read한다.

**승계 시 원칙:** 이전 회차에서 확정된 `SB-CHAR-*`와 `SB-NEVER-*`는 사용자가 명시적으로 바꾸라고 하지 않는 한 변경하지 않는다. 독자가 인물을 알아보는 근거가 이 두 축이기 때문이다.

## 2. 교차 리뷰 프로토콜

각 에이전트는 **자기 전문 렌즈로 남의 산출물**을 본다. 자기 산출물은 리뷰하지 않는다 — 자기 검수는 이미 제작 단계에서 끝났고, 교차 리뷰의 가치는 다른 전제를 가진 사람이 보는 데 있다.

### 리뷰 배정 매트릭스

| 리뷰어 | 리뷰 대상 | 렌즈 (무엇을 보는가) |
|--------|----------|---------------------|
| story-writer | 패널·대사 | 서사 의도 보존 — 비트의 감정 곡선이 컷 분할과 대사에서 유지되는가 |
| character-designer | 스토리·패널 | 캐릭터 앵커 일관성 — 인물의 행동·등장 컷이 확립된 성격/외형과 충돌하지 않는가 |
| panel-planner | 스토리·대사 | 스크롤 수용력 — 비트 수가 컷 예산에 맞는가, 대사량이 말풍선 공간에 들어가는가 |
| dialogue-editor | 스토리·패널 | 화법·분량 — 화자별 말투가 유지되는가, 컷당 텍스트 밀도가 읽히는가 |
| style-guardian | 전부 | 바이블 준수 — 모든 `SB-*` 규칙 대조 |

리뷰는 **파일 기반**이다. 각 리뷰어는 `webtoon/_workspace/06_review_{리뷰어}.md`에 쓴다. 파일로 남겨야 중재자가 상충하는 두 지적을 나란히 놓고 판정할 수 있고, 사후에 왜 이렇게 고쳤는지 추적된다.

### 리뷰 리포트 형식

```markdown
# 교차 리뷰 — {리뷰어 이름}
**렌즈:** {한 줄} | **대상:** {파일 목록} | **라운드:** {N}

## 지적 사항
| # | 대상 | 위치 | 위반 규칙 | 심각도 | 지적 | 제안 |
|---|------|------|----------|--------|------|------|
| 1 | 04_panel_layout.json | P17 | SB-RHYTHM-02 | MAJOR | 클라이맥스 직전 3컷 연속 동일 높이라 가속감이 죽음 | P16을 420px로 축소, P17을 1400px 롱컷으로 |

## 잘 맞은 지점
{유지해야 할 판단. 개정 라운드에서 실수로 되돌리는 것을 막는다.}

## 판정 불가
{바이블에 근거 규칙이 없어 판단할 수 없는 항목. 중재자가 신규 규칙을 발급해야 한다.}
```

### 심각도 기준

| 심각도 | 정의 | 처리 |
|--------|------|------|
| `BLOCKER` | `SB-NEVER-*` 위반 또는 산출물 간 참조 깨짐(존재하지 않는 패널/캐릭터 ID) | 반드시 수정. 미수정 시 조립 중단 |
| `MAJOR` | `SB-*` 규칙 위반이며 독자가 인지할 수준 | 수정 권장. 중재자가 기각 시 사유 기록 |
| `MINOR` | 규칙 위반이지만 국소적 | 개정 라운드에 여유가 있으면 반영 |
| `NOTE` | 규칙 위반은 아니나 개선 여지 | 반영 선택. 다음 회차 바이블 후보 |

**인용 없는 지적은 MINOR 이하로 강등한다.** `SB-*` ID를 인용하지 못한 지적은 취향일 가능성이 높고, 취향으로 다른 에이전트의 확정 산출물을 뒤집게 두면 개정이 수렴하지 않는다. 다만 "판정 불가"로 올린 항목은 예외 — 규칙 공백 자체가 발견이므로 중재자가 신규 `SB-*`를 발급한다.

## 3. 중재

style-guardian이 모든 리뷰를 종합해 `webtoon/_workspace/07_consistency_report.md`를 쓴다.

**충돌 판정 원칙 — 상위 규칙이 이긴다:**

```
SB-NEVER  >  SB-CHAR  >  SB-TONE / SB-ART  >  SB-RHYTHM / SB-TEXT / SB-COLOR
```

캐릭터 앵커와 컷 리듬이 충돌하면(예: 앵커 노출을 위해 클로즈업이 필요한데 리듬상 롱컷이어야 함) 앵커가 이긴다. 리듬은 회차 내에서 회복되지만 인물 붕괴는 회차를 넘어 누적되기 때문이다.

**동급 충돌 시:** 삭제하지 않고 두 안을 병기한 뒤, 사용자 결정 항목으로 리포트에 올린다. 중재자가 임의로 고르면 근거 없는 결정이 바이블에 스며든다.

**리포트 형식:**

```markdown
# 스타일 일관성 리포트 — {작품} {N}화
**라운드:** {N} | **판정:** PASS / REVISE / BLOCKED

## 요약
| 심각도 | 접수 | 채택 | 기각 |
|--------|------|------|------|

## 개정 지시
에이전트별로 묶는다. 한 에이전트가 자기 지시만 읽고 수정할 수 있어야 한다.
### → {에이전트}
| # | 대상 위치 | 지시 | 근거 규칙 | 심각도 |

## 기각 사항
| # | 지적 | 기각 사유 |

## 신규 규칙 발급
| 신규 ID | 규칙 | 발단 |

## 사용자 결정 필요
| 쟁점 | 안 A | 안 B | 영향 |
```

**판정 기준:** BLOCKER가 0이고 MAJOR가 0이면 `PASS`. MAJOR가 남으면 `REVISE`. BLOCKER가 남고 개정 라운드를 소진했으면 `BLOCKED` — 사용자에게 보고한다.

## 4. 개정 루프

**최대 2라운드.** 3라운드째부터는 개선폭이 지적 수용 비용을 밑돌고, 무한 루프 위험이 실질적이다. 2라운드 후 잔여 MAJOR는 리포트에 "미해결"로 명시하고 진행한다 — 감춘 미해결이 조용히 조립되는 것보다 낫다.

라운드 진행:
1. 각 제작 에이전트가 자기 앞 개정 지시만 읽고 산출물을 수정한다
2. 수정본은 덮어쓰지 않고 `webtoon/_workspace/08_r{N}_{artifact}` 로 저장한다 — 원본이 남아야 개정이 개악인지 판정할 수 있다
3. style-guardian이 개정본만 재검수한다. 전체 재리뷰는 하지 않는다

## 5. 산출물 정합성 검증

에이전트 간 경계면(패널 ID ↔ 대사 ID ↔ 캐릭터 이름)은 사람이 눈으로 대조하면 반드시 새는 지점이다. 스크립트로 검증한다:

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/skills/style-consistency/scripts/validate_package.py \
  --panels webtoon/_workspace/04_panel_layout.json \
  --dialogue webtoon/_workspace/05_dialogue_script.json \
  --characters webtoon/_workspace/03_character_sheet.json
```

> `${CLAUDE_PLUGIN_ROOT}`는 **셸 환경변수가 아니다.** 플러그인이 설치된 절대 경로로 직접 치환해서 실행한다 — 스킬을 호출하면 그 경로를 알 수 있다. 그대로 넘기면 `/skills/...`로 해석되어 파일을 찾지 못한다.

검사 항목: 대사가 존재하지 않는 패널을 참조하는가 / 패널이 선언한 말풍선 슬롯과 대사 스크립트가 일치하는가 / 등장 인물이 캐릭터 시트에 있는가 / 패널당 말풍선 수와 글자 수가 한계를 넘는가 / 패널 ID 중복·순서 이상.

스크립트는 `BLOCKER`(참조 깨짐)와 `MAJOR`(한계 초과)를 구분해 출력한다. 종료 코드 0=통과, 1=MAJOR만, 2=BLOCKER 존재.

이 검증은 리뷰 라운드 **시작 전에** 돌린다. 참조가 깨진 상태로 사람(에이전트)이 리뷰하면 지적이 전부 그 한 원인으로 수렴해 나머지 관점이 묻힌다.

## 6. 회차 종료 후 바이블 환류

리포트의 "신규 규칙 발급"과 "사용자 결정 필요"에서 확정된 항목을 `webtoon/series-bible.md`에 병합한다. 이 병합을 건너뛰면 다음 회차가 같은 논쟁을 반복한다.
