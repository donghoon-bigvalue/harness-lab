# YouTube Trend Research

유튜브 영상 앵글을 도출하기 위한 조사 절차. **목표는 트렌드 나열이 아니라 "수요는 있는데 좋은 영상이 없는 지점"의 특정이다.**

## 조사 모드 결정

조사 시작 전 모드를 정한다. 모드에 따라 산출물의 신뢰 수준이 달라지므로 반드시 명시한다.

| 모드 | 조건 | 산출물 표기 |
|------|------|-----------|
| **실조사** | WebSearch/WebFetch로 유의미한 결과 확보 | 표기 없음 (기본) |
| **폴백** | 검색 3회 이상 시도했으나 유의미한 결과 없음 | `> 조사 모드: 폴백 (웹 검색 불가)` + 모든 수치 제거 |
| **혼합** | 일부 축만 검색 성공 | `> 조사 모드: 혼합` + 축별로 `[검색 확인]` / `[추정]` 태깅 |

폴백 모드에서 수치를 만들어내는 것이 이 스킬의 가장 심각한 실패다. 감독자가 그 수치로 앵글을 고르고, 대본이 그 수치를 인용하며, 최종 영상이 거짓 정보를 발행하게 되기 때문이다. **수치가 없으면 정성적 판단만 남긴다.**

## 조사 4축

### 축 1 — 수요 신호

무엇을 검색하고 있는가.

- 주제 관련 검색어 자동완성 패턴 (`{주제} 방법`, `{주제} vs`, `{주제} 안될 때` 등 접미 조합)
- 커뮤니티·Q&A에서 반복되는 질문 (Reddit, 네이버 지식iN, 관련 포럼, X)
- 계절성·이벤트성 수요 (시험 시즌, 신제품 출시, 정책 변경)

검색 쿼리 예: `{주제} 2026`, `{주제} 후기`, `why {주제} not working`, `{주제} 추천 reddit`

### 축 2 — 공급 현황 (경쟁 영상)

상위 노출 영상 5~10개를 분석한다. 각각 다음을 기록한다:

| 항목 | 기록 내용 |
|------|----------|
| 제목 | 원문 + 어떤 키워드를 노렸는지 |
| 채널 규모 | 구독자 수 (알 수 있으면) |
| 조회수/업로드 시점 | 출처와 조사 시점 병기 |
| 다룬 범위 | 어떤 하위 주제를 커버했는지 |
| **빠뜨린 것** | 가장 중요. 다루지 않은 하위 주제·전제·후속 질문 |
| 썸네일 패턴 | 레이아웃/색/텍스트 유무 (thumbnail-planner에게 전달) |

### 축 3 — 미충족 질문 (댓글 마이닝)

**가장 값진 데이터다.** 상위 영상 댓글에서 다음 패턴을 수집한다:

- "그래서 결국 어떻게 하라는 거죠?" → 실행 단계 누락
- "이건 안 다뤄줬네요" → 명시적 갭
- "저는 X 상황인데 그때도 되나요?" → 조건 분기 누락
- 반복되는 반박·논쟁 → 논쟁형 앵글 후보

각 미충족 질문에 대해 반복 빈도(대략 몇 개 댓글에서 반복되는지)를 함께 기록한다.

### 축 4 — 포화도

수요가 커도 대형 채널이 완벽히 커버한 주제는 신규·중소 채널에게 무의미하다.

| 포화도 | 판단 기준 | 대응 |
|--------|----------|------|
| 낮음 | 상위 영상이 3개 미만이거나 대부분 2년 이상 됨 | 정면 공략 |
| 중간 | 상위 영상은 많지만 특정 관점·대상이 비어 있음 | 갭 공략 (권장) |
| 높음 | 대형 채널이 최근 완결성 있게 커버 | 회피하거나 정반대 입장 |

## 앵글 도출 프레임워크

축 1~4를 조합해 앵글 후보 3~5개를 만든다. 앵글은 다음 문장 틀로 검증한다:

> **{타깃}에게 {미충족 질문}을 {차별화 관점}으로 답하는 영상. 기존 상위 영상은 {빠뜨린 것} 때문에 이걸 못 한다.**

이 문장이 채워지지 않으면 앵글이 아니라 주제일 뿐이다.

**나쁜 앵글:** "AI 코딩 도구 트렌드" — 타깃도 갭도 없다.
**좋은 앵글:** "5~15명 규모 개발팀 리드에게, AI 코딩 도구 도입 후 코드 리뷰가 형식화되는 문제를 실제 팀 운영 규칙 변경안으로 답하는 영상. 기존 상위 영상은 전부 개인 생산성 관점이라 팀 프로세스 붕괴를 다루지 않는다."

앵글별로 **추천 포맷**을 판단한다:
- 배경 설명이 30초 이상 필요하거나 단계가 3개 이상 → 롱폼
- 단일 반전·단일 팁·시각적 임팩트 중심 → 숏폼
- 둘 다 가능하면 롱폼 본편 + 숏폼 훅 파생을 제안

### `youtube-content/_workspace/01_angle_candidates.md`

```markdown
# 앵글 후보

> 추천: {N}번

## 앵글 {N}: {한 줄 제목}
- **검증 문장**: {타깃}에게 {미충족 질문}을 {차별화 관점}으로 답하는 영상. 기존 상위 영상은 {빠뜨린 것} 때문에 이걸 못 한다.
- **타깃 시청자**: {구체적으로 — "개발자"가 아니라 "5~15명 팀의 개발 리드"}
- **근거**: {축 1~4 중 어디서 나왔는지}
- **추천 포맷**: {롱폼 | 숏폼 | 롱폼+숏폼 파생}
- **리스크**: {왜 실패할 수 있는가 — 반드시 하나 이상 적는다}
```

리스크 칸을 비우지 않는다. 모든 앵글에는 실패 시나리오가 있고, 감독자는 그것을 알고 골라야 한다.

## 흔한 실패

| 실패 | 왜 문제인가 | 대신 |
|------|-----------|------|
| 트렌드 키워드 나열로 끝냄 | 앵글이 아니라 주제 목록이다. 대본을 쓸 수 없다 | 검증 문장을 반드시 채운다 |
| 타깃을 "일반인", "직장인"으로 씀 | 너무 넓어 훅을 쓸 수 없다 | 상황·규모·수준을 특정한다 |
| 조회수 높은 영상 = 좋은 앵글로 착각 | 그 앵글은 이미 소진됐다 | 갭을 본다 |
| 검색 실패를 숨기고 그럴듯하게 채움 | 하류 전체가 거짓 위에 세워진다 | 폴백 모드를 선언한다 |
| 앵글 5개를 모두 매력적으로 씀 | 감독자가 고를 수 없다 | 추천 1개를 명시하고 리스크를 적는다 |
