# YouTube Content Review

발행 직전 마지막 관문. **개별 산출물의 품질이 아니라, 네 산출물이 같은 하나의 영상을 가리키는지를 검증한다.**

"대본이 잘 쓰였는가"는 작가의 일이다. 이 스킬의 일은 **"제목이 약속한 것이 대본 몇 분에 있는가"**를 확인하는 것이다.

## 핵심 원리: 존재 확인이 아니라 내용 대조

가장 흔한 검수 실패는 파일이 있는지, 항목이 채워졌는지만 보는 것이다. 그것은 검증이 아니다.

**올바른 절차:**
1. 두 파일을 동시에 연다
2. 한쪽에서 **명제**를 뽑아 적는다 (예: 제목 → "리뷰 시간이 3배 늘어난 원인을 알려준다")
3. 다른 쪽에서 그 명제가 충족되는 **구체적 위치**를 찾아 적는다 (예: 대본 04:20~05:10)
4. 찾지 못하면 결함이다

위치를 적지 못한 통과 판정은 통과가 아니다.

## 검증 경계면 5종

### 1. 제목 ↔ 대본 (약속 이행)

- `03_seo.md` 추천 제목이 약속하는 명제를 모두 나열
- 각 명제에 대해 `02_script.md`의 약속-이행 매핑에서 타임코드 확인
- 대본의 `## 다루지 않은 주제`와 제목이 겹치는지 확인

**치명적 결함:** 제목이 약속한 것이 대본에 없음 / 대본이 명시적으로 다루지 않는다고 한 것을 제목이 약속함

### 2. 썸네일 ↔ 대본 (장면 실재)

- `03_thumbnail.md`의 각 컨셉이 약속하는 장면·수치·상황을 나열
- 해당 장면이 대본의 어느 구간에 실재하는지 확인
- 썸네일의 수치가 대본의 수치와 일치하는지 확인 (반올림·과장 포함)

**치명적 결함:** 썸네일이 약속한 장면이 대본에 없음 / 수치 불일치

### 3. 제목 ↔ 썸네일 (카피 중복)

- 단어 단위 중복 확인
- **의미 중복 확인** — 다른 단어로 같은 정보를 전달하는 경우도 결함
- 제목과 썸네일이 각각 어떤 정보 축을 담당하는지, 두 축이 실제로 다른지 판정

**치명적 결함:** 의미 중복으로 정보량이 절반이 됨

### 4. 대본 ↔ 조사 자료 (사실 근거)

- 대본의 **모든** 수치·고유명사·인용·구체적 사례를 나열
- 각각에 대해 `01_trend_research.md`의 `6. 대본용 사실·사례`에서 출처를 찾는다
- 출처 없는 항목은 전부 결함

**조사 모드가 폴백인 경우:** 조사 자료에 수치가 없는 것이 정상이다. 이때 대본에 수치가 등장하면 그 자체가 치명적 결함이다 (작가가 지어냈다는 뜻).

**치명적 결함:** 출처 없는 수치·인용 / 조사 자료와 값이 다름 / `[근거 필요]` 플레이스홀더가 남아 있음

### 5. 앵글 일관성 (전체)

- `01_angle_candidates.md`의 확정 앵글 검증 문장을 읽는다
- 대본·제목·썸네일이 모두 **같은 타깃**에게 **같은 미충족 질문**을 답하고 있는지 확인
- 특히 타깃 드리프트를 본다 — 앵글은 "5~15명 팀 리드"인데 대본이 "개발자 일반"에게 말하고 있으면 결함

**치명적 결함:** 타깃 또는 논지가 산출물 간에 어긋남

## 추가 점검

### 낚시성

클릭률만 올리고 시청 지속률을 깎는 요소를 찾는다. 판정 기준은 하나다: **약속과 이행의 거리**.

| 상태 | 판정 |
|------|------|
| 제목·썸네일이 약속한 것이 대본 전반부에 이행 | 정상 |
| 마지막에만 이행 | 개선 제안 (치명적 아님) |
| 이행되지 않음 | 치명적 결함 |
| 대본 내용보다 강도가 과장됨 (예: "완전 해결" vs 대본은 "부분 개선") | 치명적 결함 |

### 정책·리스크

- 의료·금융·법률 관련 단정적 조언 (면책 문구 필요 여부)
- 타 브랜드·인물에 대한 근거 없는 부정적 단정
- 저작권 소재 사용 지시 (B-roll, 음원, 인용 이미지)
- 미성년 대상 콘텐츠 여부 표기 필요성

### 실행 가능성

- 대본의 화면 지시가 실제로 촬영·편집 가능한지 (구간마다 지시가 있는지)
- 챕터 타임코드가 `00:00`으로 시작하는지
- 이미지 생성 프롬프트에 한글 텍스트가 들어가지 않았는지

## 판정 기준

| 판정 | 조건 |
|------|------|
| **PASS** | 치명적 결함 0건. 개선 제안은 몇 건이든 무방 |
| **REVISE** | 치명적 결함 1건 이상 |

**치명적 결함과 개선 제안을 엄격히 구분한다.** 재작업 루프는 감독자가 2회로 제한한다. 사소한 지적으로 소진되면 정작 중요한 결함을 고칠 기회가 사라진다.

- 치명적: 사실 오류, 약속 불이행, 앵글 불일치, 정책 위반, 실행 불가
- 개선 제안: 더 강한 훅 가능, 카피 표현 다듬기, 태그 추가 여지, 구간 배분 조정

"훅이 약함" 같은 서술은 쓰지 않는다. **위치와 방향을 적는다**: "훅이 30초까지 이어지는데 롱폼 기준 15초 내 약속 제시 없음 — 25~30초 배경 설명을 프레이밍 구간으로 이동 권장."

## 재검수 시

전체를 다시 보지 않는다.

1. 이전 회차의 치명적 결함 목록을 항목별로 해소 여부 확인
2. **수정으로 새로 깨진 경계면만** 추가 검증 — 예: 제목이 바뀌었으면 경계면 1·3을 다시, 대본이 바뀌었으면 1·2·4를 다시
3. `## 회차 이력`에 누적 기록

수정 이력은 `02_script.md`의 `## 수정 이력` 섹션에서 무엇이 바뀌었는지 확인한다.

## 에러 핸들링

| 상황 | 처리 |
|------|------|
| 입력 파일 일부 누락 | 해당 경계면을 `검증 불가`로 표시. **통과로 처리하지 않는다** |
| 조사 자료가 폴백 모드 | 사실 근거 추적은 건너뛰되, 대본에 수치가 있으면 치명적 결함 |
| 대본에 `[근거 필요]` 잔존 | 치명적 결함 (미완성 상태 발행 방지) |
| 판정 애매 | 결함이 치명적 기준에 미달하면 PASS + 개선 제안 |

## 흔한 실패

| 실패 | 왜 문제인가 | 대신 |
|------|-----------|------|
| 파일 존재·항목 채움만 확인 | 검증이 아니다 | 두 파일을 대조하고 위치를 적는다 |
| 근거 위치 없이 "통과" | 검증했다는 증거가 없다 | 타임코드·행 번호를 반드시 적는다 |
| 개선 제안으로 REVISE | 2회 루프를 낭비한다 | 치명적 기준을 엄격히 적용 |
| "훅이 약함" 식 서술 | 무엇을 고칠지 알 수 없다 | 위치 + 방향 |
| 팀원에게 직접 수정 지시 | 상충 지시가 발생한다 | 감독자에게만 보고 |
| 누락 파일을 통과 처리 | 검증되지 않은 채 발행된다 | `검증 불가`로 명시 |
