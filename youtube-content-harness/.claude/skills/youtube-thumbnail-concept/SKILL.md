# YouTube Thumbnail Concept

썸네일 컨셉을 설계하고 **디자이너나 이미지 생성 모델이 그대로 실행할 수 있는 지시서**를 만든다. 추상적 무드보드가 아니라 실행 명세다.

## 전제: 모바일 크기

실제 노출 크기는 폭 200px 이하다. 데스크톱 미리보기에서 멋진 디테일은 모바일에서 소음이 된다.

| 항목 | 상한 | 이유 |
|------|------|------|
| 시각 요소 | 3개 이하 | 그 이상은 200px에서 뭉개진다 |
| 카피 | 3~5단어 / 한글 9자 내외 | 읽히지 않으면 없는 것과 같다 |
| 폰트 굵기 | Bold 이상 | 얇은 폰트는 축소 시 사라진다 |
| 주 피사체 | 1개 | 시선이 갈라지면 0.3초 안에 인식 실패 |

**검증법:** 완성 컨셉을 200px 폭으로 축소했다고 상상하고, 그래도 주제가 읽히는지 자문한다. 읽히지 않으면 요소를 줄인다.

## 레이아웃 아키타입

컨셉 2~3안은 **서로 다른 아키타입**에서 뽑는다. 같은 아키타입의 변형 3개는 A/B 테스트 가치가 없다.

| 아키타입 | 구조 | 강한 앵글 | 카피 역할 |
|---------|------|----------|----------|
| **대비형 (A vs B)** | 화면 좌우 분할, 두 상태 병치 | 비교·전후·선택 | 두 축의 이름 또는 결과 차이 |
| **결과 수치형** | 큰 숫자 1개 + 맥락 최소화 | 실험·기록·성과 | 숫자의 단위/의미 |
| **인물 반응형** | 인물 클로즈업 + 감정 표현 | 경험담·리액션·경고 | 인물이 반응하는 대상 |
| **객체 중심형** | 대상물 클로즈업, 배경 제거 | 리뷰·언박싱·도구 | 대상의 정체 또는 반전 |
| **금지·경고형** | 대각선 취소선, 적색 강조 | 실수·오해·주의 | 하지 말아야 할 것 |
| **다이어그램형** | 단순 도식 3요소 이하 | 개념·구조 설명 | 핵심 개념어 |

**인물 반응형을 습관적으로 쓰지 않는다.** 얼굴은 강력하지만, 정보성·비교형 콘텐츠에서는 대비형이나 결과 수치형이 더 강하다. 인물의 감정 표현이 앵글과 실제로 맞을 때만 쓴다.

## 차별화 — 검색 결과 화면에서 혼자 다르게

`01_trend_research.md`의 `7. 경쟁 썸네일 시각 패턴`을 반드시 확인한다. 노란 자막에 놀란 표정이 이미 8개면 9번째는 보이지 않는다.

차별화 축 (하나 이상 선택):
- **색**: 경쟁이 노랑·빨강 위주면 → 딥블루·단색 배경·무채색+단일 강조색
- **밀도**: 경쟁이 요소 과밀이면 → 극단적 여백
- **구도**: 경쟁이 인물 클로즈업이면 → 객체 중심 또는 다이어그램
- **톤**: 경쟁이 과장된 감정이면 → 담담한 정보형

각 컨셉에 **어떤 축으로 차별화했는지** 명시한다.

## 카피 설계

### 제목과 절대 중복하지 않는다

같은 말을 두 번 하면 정보량이 절반이 된다. seo-optimizer와 SendMessage로 역할을 나눈다:

- **제목이 "무엇을"** → 썸네일은 **"왜 / 얼마나 / 그래서 어떻게 됐는지"**
- 제목: "AI 도구 도입 후 코드리뷰가 망가지는 이유" → 썸네일 카피: **"리뷰 3배 ↑"** (결과 수치를 담당)
- 제목: "리뷰 시간 3배 늘어난 팀, 뭘 잘못했나" → 썸네일 카피: **"규칙 1개 때문"** (원인을 담당)

단어 단위 중복뿐 아니라 **의미 중복**도 피한다. "망가짐"과 "붕괴"는 다른 단어지만 같은 정보다.

### 카피 패턴

| 패턴 | 예 | 적합 |
|------|-----|------|
| 결과 수치 | "3배 ↑", "-72%" | 실험·기록 |
| 부정 지시 | "하지 마세요" | 실수·주의 |
| 반전 선언 | "사실 반대" | 통념 반박 |
| 대상 지목 | "팀장이라면" | 정밀 타깃 |
| 미완 문장 | "그런데 여기서…" | 호기심 (남용 주의) |

### 무자막 검증

자막 없이 구도만으로 주제가 전달되면 가장 강한 썸네일이다. 각 컨셉에 대해 **"카피를 가려도 주제가 읽히는가"**를 자문하고 결과를 기록한다.

## 색·시선

- **배경과 주피사체의 명도 대비를 최대로.** 축소 시 형태를 유지하는 유일한 방법이다
- **강조색은 1개.** 2개 이상이면 시선이 갈라진다
- **시선 흐름을 지정한다**: 진입점(가장 먼저 보이는 것) → 두 번째 → 세 번째. 3단계를 넘기지 않는다
- 유튜브 UI에 가려지는 영역을 피한다: **우측 하단**(재생 시간 표시), 하단 얇은 띠(진행바)

## 이미지 생성 프롬프트

각 컨셉마다 이미지 생성 모델용 프롬프트를 1개 작성한다. 포함할 것:

- 화면비 (16:9, 1280×720)
- 구도와 피사체 위치 (좌/중앙/우, 클로즈업/미디엄)
- 배경 (단색 지정 시 색상값)
- 조명·톤
- **텍스트는 프롬프트에 넣지 않는다** — 이미지 모델의 한글 렌더링은 신뢰할 수 없다. 카피는 후처리로 얹는다는 것을 지시서에 명시한다

## A/B 테스트 계획

무엇을 다르게 하고 무엇으로 판정할지 적는다. **한 번에 한 변수만** 바꾼다 — 두 개를 동시에 바꾸면 무엇이 효과를 냈는지 알 수 없다.

```markdown
## A/B 계획
- **변수**: 아키타입 (대비형 vs 결과 수치형)
- **고정**: 카피, 색 팔레트
- **판정 지표**: 노출 클릭률 (CTR)
- **판정 조건**: 노출 1,000회 이상 확보 후 비교
- **다음 라운드**: 승자 아키타입 고정 후 카피 문구를 변수로
```

## 흔한 실패

| 실패 | 왜 문제인가 | 대신 |
|------|-----------|------|
| 요소 5개 이상 배치 | 200px에서 전부 뭉개진다 | 3개 이하 |
| 카피가 한 문장 | 읽을 시간이 없다 | 3~5단어 |
| 제목과 같은 말 | 정보량 절반 손실 | 역할 분담 후 카피 작성 |
| 습관적 놀란 표정 | 경쟁 썸네일과 구분되지 않는다 | 아키타입 표에서 앵글에 맞는 것 선택 |
| 컨셉 3안이 같은 아키타입 변형 | A/B 테스트 가치 없음 | 서로 다른 아키타입에서 뽑는다 |
| 대본에 없는 장면 약속 | 낚시 — 시청 지속률 붕괴 | 대본 근거 매핑 필수 |
| 이미지 프롬프트에 한글 텍스트 포함 | 렌더링이 깨진다 | 텍스트는 후처리로 명시 |
