# YouTube SEO Optimization

유튜브 메타데이터를 설계한다. **검색에 걸리지만 클릭되지 않는 제목과, 클릭되지만 검색에 안 걸리는 제목은 둘 다 실패다.**

성과 = 노출 × 클릭률 × 시청 지속률. 세 항목이 곱셈이므로 하나만 극대화하는 최적화는 의미가 없다. 특히 과장 제목으로 클릭률을 올리면 시청 지속률이 떨어져 총 성과가 하락한다.

## 제목 설계

### 첫 30자 규칙

모바일 검색·추천 화면에서 제목은 **약 30자 전후에서 잘린다**. 따라서:

- 핵심 키워드와 후킹 요소를 앞쪽 30자에 배치한다
- 뒤쪽은 잘려도 의미가 통하는 보조 수식어만 둔다
- 제목 5안마다 **글자수와 잘림 지점을 명시**한다

```
제목: AI 도구 쓰고 팀 코드리뷰가 망가졌습니다 | 3개월 복구 기록
      └────────── 27자, 여기까지 노출 ──────────┘
```

### 제목 5안 구성

노림수가 다른 5안을 쓴다. 전부 같은 유형이면 감독자가 선택할 근거가 없다.

| 유형 | 겨냥 | 구성 | 예 |
|------|------|------|-----|
| **검색형** | 노출 | 키워드를 앞에, 검색어 형태 그대로 | "AI 코딩 도구 팀 도입 방법 — 리뷰 문화까지 지키는 법" |
| **CTR형** | 클릭 | 호기심·손실회피, 키워드는 뒤 | "3개월 만에 팀 코드리뷰가 형식만 남았습니다" |
| **균형형** | 둘 다 | 키워드 + 후킹 요소 결합 | "AI 도구 도입 후 코드리뷰가 망가지는 이유" |
| **수치형** | 신뢰 | 구체적 숫자를 앞에 | "리뷰 시간 3배 늘어난 팀, 뭘 잘못했나" |
| **대상 지목형** | 정밀 타깃 | 타깃을 명시 | "5~15명 개발팀 리드가 놓치는 AI 도입 함정" |

각 안에 **노림수 / 글자수 / 잘림 지점 / 예상 약점**을 붙인다. 그리고 추천 1안을 근거와 함께 명시한다.

### 추천안 선택 기준

- 조사 자료의 포화도가 **높음**이면 → CTR형·대상 지목형 (검색 경쟁이 불리하므로 차별화로 승부)
- 포화도가 **낮음~중간**이면 → 검색형·균형형 (검색 유입을 선점)
- 조사가 **폴백 모드**(키워드 데이터 없음)이면 → CTR형 비중을 높인다. 검증되지 않은 키워드에 베팅하는 것보다 사람에게 통하는 제목이 안전하다

### 금지

- 대본에 없는 것을 약속하는 제목. 반드시 `02_script.md`의 `## 다루지 않은 주제`를 확인한다
- 전체 대문자·과도한 특수문자·이모지 남발 (신뢰도 하락)
- 키워드 나열형 ("AI 코딩 도구 리뷰 추천 비교 2026 최신") — 사람이 클릭하지 않는다

## 설명란

### 첫 2~3줄 (더보기 이전)

검색 결과와 영상 하단에 노출되는 **유일하게 읽히는 부분**이다. 여기에:

1. 제목이 한 약속을 한 문장으로 재확인 + 핵심 키워드 자연 배치
2. 영상이 주는 구체적 결과
3. (선택) 가장 강한 챕터 하나를 미리 지목

나머지 링크·출처·소개는 그 아래로.

### 챕터

`02_script.md`의 타임코드를 그대로 가져온다. 규칙:

- **반드시 `00:00`으로 시작**한다 (없으면 챕터가 생성되지 않는다)
- 최소 3개, 각 챕터 최소 10초
- 챕터명은 내용 요약이 아니라 **검색될 만한 표현**으로 (예: "본론 2" ✗ → "팀 규칙 3가지 변경안" ✓)

### 구조 템플릿

```
{제목 약속 재확인 + 키워드}. {구체적 결과 한 문장}.
{가장 강한 챕터 지목}

⏱ 챕터
00:00 {}
...

📌 영상에서 언급한 자료
- {출처}: {링크}

{채널 소개 2~3줄}
{관련 영상 링크}

#{해시태그1} #{해시태그2} #{해시태그3}
```

## 태그·해시태그

**태그의 실질 효과는 제한적이다.** 유튜브는 제목·설명·자막·시청 행동으로 주제를 판단한다. 태그에 과투자하지 말고, 다음 보조 역할에만 쓴다:

| 구성 | 개수 | 역할 |
|------|------|------|
| 핵심 키워드 + 변형 | 5~7 | 주제 신호 |
| 롱테일 (3단어 이상) | 5~8 | 정밀 매칭 |
| 동의어·영문/한글 병기 | 3~5 | 표기 차이 커버 |
| 오탈자·띄어쓰기 변형 | 2~3 | 검색 실수 커버 |
| 채널명·시리즈명 | 1~2 | 자사 영상 연결 |

총 15~25개. 500자 제한을 넘기지 않는다.

**해시태그는 3개만.** 4개 이상 넣으면 유튜브가 전부 무시한다. 제목 위에 앞의 3개가 표시되므로, 클릭 유도력이 있는 것을 고른다.

## 정합성 검증 (필수)

산출물을 내기 전 반드시 수행한다. content-reviewer가 가장 자주 REVISE를 내는 지점이다.

| 검증 항목 | 방법 | 실패 시 |
|----------|------|--------|
| 제목 약속 ↔ 대본 이행 | 추천 제목이 약속하는 명제를 적고, `02_script.md`의 약속-이행 매핑에서 해당 타임코드를 찾는다 | 제목을 바꾸거나 감독자에게 대본 보완 제안 |
| 제목 ↔ 다루지 않은 주제 | 대본의 `## 다루지 않은 주제`와 제목이 겹치지 않는지 | 제목 수정 |
| 제목 ↔ 썸네일 카피 | thumbnail-planner의 카피와 단어·의미 중복 여부 | SendMessage로 역할 분담 재합의 |
| 챕터 타임코드 ↔ 대본 | 모든 챕터가 실제 대본 구간과 일치하는지 | 타임코드 수정 |

**제목-썸네일 역할 분담 원칙:** 제목이 "무엇을"이면 썸네일은 "왜 / 얼마나 / 그래서 어떻게 됐는지"를 맡는다. 같은 말을 두 번 하면 정보량이 절반이 된다.

## 흔한 실패

| 실패 | 왜 문제인가 | 대신 |
|------|-----------|------|
| 제목 5안이 전부 비슷한 유형 | 선택 근거가 없다 | 유형 표의 5종을 각각 하나씩 |
| 글자수·잘림 지점 미표기 | 모바일에서 핵심이 잘린다 | 안마다 명시 |
| 키워드를 억지로 앞에 배치 | 부자연스러워 클릭되지 않는다 | 자연스러운 문장 우선, 키워드는 그 안에 |
| 태그를 30개 이상 나열 | 효과 없고 스팸 신호 | 15~25개, 역할별 구성 |
| 챕터가 00:00으로 시작하지 않음 | 챕터가 아예 생성되지 않는다 | 반드시 00:00 포함 |
| 썸네일 카피 확인 없이 제출 | 중복 시 CTR 손실 + REVISE | SendMessage로 사전 합의 |
