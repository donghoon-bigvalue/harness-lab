# A/B Test Planning — A/B 테스트 설계

캠페인을 "추측"에서 "학습"으로 바꾼다. 목표는 실험 목록 나열이 아니라, **각 실험이 무엇을 배우는지 명확하고, 변수가 격리되어 결과가 해석 가능한 테스트 계획**이다.

## 설계 절차

### 1. 입력 정렬
`00_brief.md`(성공 지표·우선순위 변수), `02_ad_copy.md`(카피 변형), `03_visual_concept.md`(비주얼 변형)를 읽는다. 무엇이 가장 불확실하고 임팩트가 큰지 — 리드가 준 우선순위 — 부터 테스트 순서를 잡는다.

### 2. 가설 먼저, 변형은 그 다음
각 실험은 명제로 시작한다: **"{변수}를 {A}로 하면 {B}보다 {지표}가 높다 — 왜냐하면 {기둥/근거}"**. 가설 없는 "그냥 둘 다 돌려보자"는 결과가 나와도 학습이 없다.

### 3. 변형 매트릭스 — 한 번에 한 변수
한 실험에서는 **하나의 변수만** 바꾼다. 나머지는 고정한다:

| 테스트 가능 변수 | 격리 방법 |
|-----------------|----------|
| 헤드라인/소구 각도 | 비주얼·CTA 고정, 헤드라인만 교체 |
| 키 비주얼 | 카피·CTA 고정, 비주얼만 교체 |
| CTA | 나머지 고정, CTA 문구/형태만 교체 |
| 오퍼 | 나머지 고정, 오퍼 조건만 교체 |

헤드라인과 비주얼을 동시에 바꾸면 무엇이 효과를 냈는지 알 수 없다.

### 4. 지표 체계
- **1차 지표**: 성공을 판정하는 단 하나 (예: 전환율, CTR)
- **2차 지표**: 맥락 (예: 체류, 스크롤 깊이)
- **가드레일 지표**: 악화되면 안 되는 것 (예: 이탈률, 환불, 브랜드 인식) — 1차만 보면 국소 최적에 빠진다

### 5. 표본·기간·순서
- **표본/기간**: "충분한 데이터"가 무엇인지 트래픽·전환율 가정으로 설명. 정밀 검정력 계산이 어려우면 가정과 최소 기준을 명시 (근거 없는 "1주일" 지양)
- **순서(로드맵)**: 가장 임팩트 큰 변수부터. 버튼 색보다 핵심 소구가 먼저
- **다음 액션**: 이기면 무엇을 하고, 차이 없으면 무엇을 배우는지 미리 적는다

## 출력 형식

`marketing/_workspace/04_ab_test_plan.md` (감독자가 전달한 정확한 경로 사용):

```markdown
# A/B 테스트 계획

## 테스트 로드맵 (우선순위 순)
1. T1 — {변수} · [P#]  2. T2 — …

## T1. {테스트 이름} — [P1] · 변수: 헤드라인 소구
- 가설: {A}로 하면 {B}보다 {지표}↑ — 근거: {기둥/조사}
- 변형: 
  - A(대조): {카피 세트 A 헤드라인} — 나머지 고정
  - B(실험): {변형 A-2 헤드라인} — 헤드라인만 교체
- 1차 지표: {…} | 2차: {…} | 가드레일: {…}
- 성공 기준: {무엇이 얼마면 B 채택}
- 표본/기간: {가정 + 최소 기준}
- 다음 액션: {이기면 / 차이 없으면}

## 측정 전제와 한계
- 트래픽·전환 가정: {…}
- 측정 가능한 지표 / 인프라 필요: {…}
```

## 핵심 원칙

- **한 실험은 한 변수만.** 변수를 격리하지 않은 테스트는 데이터를 낭비한다.
- **가설을 먼저 써라.** "이걸 배우기 위해 이걸 바꾼다"가 없으면 결과가 무의미하다.
- **중요한 것부터.** 가장 불확실하고 임팩트 큰 변수를 먼저. 버튼 색은 나중이다.
- **가드레일 지표를 반드시.** 전환은 올랐는데 이탈·환불이 나빠질 수 있다.
- **표본을 근거로.** 근거 없는 기간 설정은 결론을 못 낸다. 가정을 명시하라.
- **변형이 없으면 테스트 불가.** 통제된 대조(한 변수만 다른 쌍)가 없으면 copywriter/디자이너에게 요청하고, 없으면 "변형 필요"로 명시한다.
