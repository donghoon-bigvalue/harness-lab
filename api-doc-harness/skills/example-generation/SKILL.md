# Example Generation — API 사용 예제 생성

설명이 말로 한 사용법을 실제 요청과 응답으로 보여준다. 예제는 문서에서 가장 먼저 읽히고 가장 자주 복사되므로, **스펙과 정합하고 복사→치환→실행이 되는 예제**가 목표다.

## 생성 절차

### 1. 스펙 정합을 기준선으로 잡는다
`01_endpoints.md`의 `E번호` 레코드가 정합 기준이다. 예제의 메서드·경로·파라미터·인증·응답 형태가 레코드와 어긋나면 틀린 예제다. 레코드에 없는 헤더·필드를 예제에 넣지 않는다. 응답 형태·인증이 불충분하면 endpoint-analyzer에 질의한다.

### 2. 대표 호출 예제를 만든다
- **curl(기본)**: 메서드·경로·헤더·본문이 완전한, 그대로 실행 가능한 형태
- **언어 스니펫**: `00_scope.md`가 지정한 언어(예: JS `fetch`, Python `requests`). 지정이 없으면 curl만
- 베이스 URL은 `https://api.example.com` 같은 플레이스홀더 + 문서 상단에서 치환 안내

### 3. 현실적인 값을 쓴다
`"string"`·`"example"` 대신 도메인에 맞는 값(`"2026-07-24"`, `"user_a1b2c3"`, `"ord_98765"`)을 쓴다. 소비자가 값에서 형식을 유추할 수 있어야 한다. 요청 본문은 필수 필드를 모두 갖추고, 선택 필드는 대표적인 것 한둘을 포함한다.

### 4. 인증을 빠뜨리지 않는다
레코드가 인증 필요로 표시한 엔드포인트의 예제에는 인증 헤더(`Authorization: Bearer <token>` 등 레코드의 스킴)를 반드시 포함한다. 인증 없는 예제는 즉시 401을 부른다. 인증 방식이 불명확하면 자리를 `<확인 필요>`로 두고 doc-lead에 보고한다.

### 5. 응답 예시를 스펙에 맞춰 만든다
레코드의 성공 응답 형태(필드·타입·중첩)에 맞춘 샘플 JSON을 보인다. 레코드가 "확인 불가"인 응답은 지어내지 말고 "응답 형태는 런타임 검증 필요"로 표기하거나, 확실한 필드만 담은 부분 예시에 한계를 주석으로 단다.

### 6. 대표 에러 케이스를 넣는다
성공만으로는 절반이다. 소비자가 가장 자주 부딪히는 실패를 재현 가능한 형태로 보인다:
- **400** 검증 실패(잘못된/누락 필드) — 요청과 실제 에러 응답
- **401** 인증 누락/만료 (인증 엔드포인트)
- **404** 없는 자원 (경로 파라미터를 받는 엔드포인트)
레코드의 에러 응답 형태에 맞춘다. 코드에 없는 에러를 지어내지 않는다.

### 7. 다단계 흐름을 연결한다
자원을 생성한 뒤 그 ID로 조회하는 흐름은, 첫 응답의 값이 다음 요청에 어떻게 들어가는지 순서와 연결을 명시한다.

## 출력 형식

description-writer가 세운 `api-reference.md`의 각 엔드포인트 `### 예제` 자리를 채운다. **뼈대·설명 섹션은 건드리지 않는다.** 각 블록에 대상 `E번호`를 주석으로 태깅:

```markdown
### 예제  <!-- E1 -->

**요청 (curl)**
​```bash
curl -X POST https://api.example.com/api/v1/orders \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "item_id": "sku_1234",
    "quantity": 2
  }'
​```

**요청 (JavaScript)**
​```js
const res = await fetch("https://api.example.com/api/v1/orders", {
  method: "POST",
  headers: { Authorization: `Bearer ${token}`, "Content-Type": "application/json" },
  body: JSON.stringify({ item_id: "sku_1234", quantity: 2 }),
});
​```

**성공 응답 `201 Created`**
​```json
{ "id": "ord_98765", "status": "pending", "total": 47.98 }
​```

**에러 예 `400 Bad Request`** — quantity 누락
​```json
{ "error": "validation_failed", "details": { "quantity": "required" } }
​```
```

## 핵심 원칙

- **스펙과 정합해야 한다.** 레코드의 메서드·경로·파라미터·인증·응답과 어긋나는 예제는 틀린 예제다. 어긋남이 필요하면 analyzer에 확인한다.
- **값은 현실적으로.** 무의미한 플레이스홀더 대신 도메인 예시값. 형식을 유추할 수 있게.
- **인증을 반드시 포함한다.** 인증 필요 엔드포인트의 예제에 인증 헤더가 없으면 실행 즉시 실패한다.
- **에러도 계약이다.** 흔한 실패를 재현 가능하게 보인다. 코드에 없는 에러를 지어내지 않는다.
- **응답을 지어내지 않는다.** "확인 불가" 응답은 그 한계를 명시한다.
- **다른 팀원의 산출물을 보존한다.** 예제 자리만 채우고 설명·뼈대는 손대지 않는다.
