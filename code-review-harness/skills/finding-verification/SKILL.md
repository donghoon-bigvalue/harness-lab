# Finding Verification — 검증·트리아지

네 감사가 끝난 뒤, **흩어진 발견을 하나의 신뢰할 수 있는 목록으로 수렴**시킨다. 개별 감사원의 정오 판정이 아니라, 발견 간 대조·오탐 제거·심각도 정규화가 목표다. 이 단계가 없으면 통합 리포트는 오탐과 중복이 섞인 네 파일의 단순 합이다.

## 검증 절차

### 1. 대조 정렬
`01~04_findings.md`를 동시에 열고, **위치(파일:줄)와 근본원인으로 정렬**한다. 이 정렬이 없으면 중복·교차를 못 잡는다. `00_scope.md`의 심각도 기준을 정규화의 기준선으로 삼는다.

### 2. 분류
| 분류 | 정의 | 처리 |
|------|------|------|
| **확인** | 근거·악용경로·재현 논리 성립하는 실제 결함 | 정규화 심각도로 리포트 포함 |
| **오탐** | 완화 존재 / 의도된 동작 / 근거 미성립 | 본문 제외, 이유를 부록에(삭제 아님) |
| **중복** | 여러 축·레코드가 같은 근본원인 | 하나로 병합, 원본 ID 병기 |
| **교차** | 한 축 발견이나 다른 축 영향 큼(예: 성능↔DoS) | 재분류·연결, 최고 심각도 축 기준 |
| **미결** | 완화·실측·맥락 부족으로 판정 불가 | 유보 표기, 보강 트리거 |

### 3. 오탐 적극 검증
'추정'·'의심' 태그 발견은 근거를 직접 대조한다. 보안은 완화 존재(상위 계층 검증)를, 성능은 실측 없는 추정을, 스타일은 관례 근거를 확인한다. 확인되면 '확인', 못 하면 '미결'. **삭제하지 말고** 오탐은 이유와 함께 부록에 남긴다.

### 4. 심각도 정규화 (핵심 가치)
네 감사원은 각자 잣대로 심각도를 매겼다. 리드의 공통 기준(**악용/장애 경로 × 조건 현실성 × 영향 범위**)으로 전부 다시 매긴다. 보안의 High와 스타일의 High가 같은 무게가 되어야 통합 리포트 순위가 의미를 갖는다.

### 5. 교차 발견 묶기
같은 코드를 서로 다른 축이 지목했으면(예: 무제한 루프 = 성능 병목 + DoS) 하나의 교차 발견으로 묶고, 최고 심각도 축 기준으로 심각도를 매기되 양쪽 관점을 병기한다. 이 연결이 단일 축 리뷰가 못 내는 통합의 가치다.

### 6. 공백 도출
판정 못 한 미결과, 특정 축이 비어 대조 불가한 발견을 목록화한다 → 보강 트리거이자 리포트의 미결 항목.

## 출력 형식

`code-review/_workspace/05_verification.md` (감독자가 전달한 정확한 경로 사용):

```markdown
# 검증·트리아지 결과
> 검증 회차: {n} | 입력 축: {감사된 축, 미감사 축 명시}

## 분류 매트릭스
| 원본 ID | 발견 | 분류 | 정규화 심각도 | 비고(병합/교차/오탐 사유) |
|---------|------|------|--------------|---------------------------|
| SEC-2, PERF-4 | 무제한 페이지 크기 | 교차 | Critical | 성능 병목 = DoS, 병합 |
| STYLE-1 | ... | 오탐 | — | 상위에서 완화됨 |

## 확인된 발견 (심각도 순)
{ID·위치·정규화 심각도·근거 요약}

## 교차 발견
{묶인 원본 ID + 양축 관점}

## 오탐 부록
{제거된 발견 + 왜 오탐인가}

## 검증 공백 (보강 필요)
{미결 발견 ID + 무엇이 부족한가(완화/실측/맥락) + 담당 축}
```

## 핵심 원칙

- **개별 검증이 아니라 발견 간 대조다.** 네 파일을 위치·근본원인으로 정렬해야 성립한다.
- **오탐을 적극 걸러내되 삭제하지 않는다.** 왜 오탐인지가 정보다.
- **확신도 낮은 발견을 확인으로 올리지 않는다.** 확인 불가면 '미결'.
- **심각도 정규화가 이 축의 핵심이다.** 공통 잣대로 다시 매긴다.
- **교차 발견을 놓치지 않는다.** 축을 넘나드는 연결이 통합의 가치다.
