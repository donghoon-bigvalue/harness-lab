# Data Validation — 검증·품질 규칙 설계

파이프라인을 통과하는 데이터가 믿을 수 있는지 검사하는 규칙을 설계한다. 스키마 카탈로그가 계약이라면, 검증은 그 계약이 실행 시점에 실제로 지켜지는지 확인하는 관문이다. 목표는 규칙 나열이 아니라, **필드 ID로 태깅되고 심각도·행동이 명시된 실행 가능한 규칙**이다.

## 검증 계층 (네 축으로 도출)

카탈로그·ETL을 훑으며 각 계층에서 규칙을 뽑는다. 계층이 곧 검사 범위다.

### 1. 형식 (Format)
필드 하나가 스스로 만족해야 할 것. 카탈로그 타입·제약에서 직접 나온다:
- 타입·null 여부(NOT NULL), 범위(CHECK ≥ 0), 열거(status ∈ {집합}), 패턴(이메일·전화 정규식), 길이

### 2. 무결성 (Integrity)
레코드 간·테이블 간 관계:
- PK 유일성, FK 참조 존재(고아 레코드 없음), 그레인 중복 없음, 크로스 필드(주문일 ≤ 배송일)

### 3. 비즈니스 (Business)
도메인 불변식. 타입 검사로 안 잡힌다 — 아키텍트·원천에게 도메인 규칙을 확인해 규칙화한다:
- "환불액 ≤ 결제액", "상태 전이 규칙", "합계 = 부분의 합", "활성 고객만 주문 가능"

### 4. 신선도/양 (Freshness/Volume)
데이터가 형식은 맞아도 안 들어왔거나 급변하면 문제:
- 최신성(어제치 존재), 행 수 범위(전일 대비 ±X%), NULL 비율 급증, 분포 이상(이 계층은 모니터링과 임계값 공유)

## 규칙별 결정 사항

각 규칙에 반드시 지정한다:

- **대상 필드/엔티티**: 카탈로그 ID로 태깅(`E1.amount`). 무엇을 지키는 규칙인지 명확히
- **검증 위치**: 추출 후(원천 품질) / 변환 후(로직 정확성) / 적재 후(최종 계약)
- **심각도**: block(중단) vs warn(경고). "이 데이터가 틀리면 하류 의사결정이 망가지는가"로 판단. 전부 block이면 사소한 이상에 멈추고, 전부 warn이면 나쁜 데이터가 통과한다
- **위반 시 행동**: 파이프라인 중단 / 격리(quarantine 테이블로 분리) / 로그·알림만. 탐지로 끝내지 않고 대응까지 정한다

## 출력 형식

`data-pipeline/_workspace/03_validation.md` (감독자가 전달한 정확한 경로 사용):

```markdown
# 데이터 검증 규칙 설계
> 설계시점: {YYYY-MM-DD}

## V1. {규칙명} [E1.amount]
- 계층: 형식 | 무결성 | 비즈니스 | 신선도/양
- 규칙: E1.amount IS NOT NULL AND E1.amount >= 0
- 검증 위치: 적재 후(post-load)
- 심각도: 차단(block) | 경고(warn)
- 위반 시 행동: 파이프라인 중단 | 격리(quarantine) | 로그·알림
- 근거: 음수 금액은 환불 오류 신호, 하류 매출 집계 오염

## V2. ...

## 규칙-필드 커버리지 매트릭스
| 카탈로그 제약 | 대응 규칙 | 심각도 |
|--------------|----------|--------|
| E1.order_id PK 유일 | V3 | block |
| E1.amount CHECK≥0 | V1 | block |
| E2.email UNIQUE | — (누락) | — |

## 미해결/확인 필요
- 도메인 규칙 확인 필요 항목 (아키텍트 확인 대기)
- block 규칙 목록 (모니터링에 알림 요구로 전달)
```

## 핵심 원칙

- **카탈로그 제약을 규칙으로 실체화한다.** NOT NULL·CHECK·UNIQUE·FK는 선언일 뿐, 검증 규칙으로 옮겨야 지켜진다. 제약 있는데 규칙 없는 필드는 통합 리뷰에서 누락으로 걸린다.
- **심각도는 하류 영향으로 정한다.** 남발한 block은 파이프라인을 멈추고, 남발한 warn은 나쁜 데이터를 통과시킨다.
- **행동까지 정한다.** 위반 시 무엇을 멈추고/격리하고/알리는지 없으면 탐지가 무의미하다.
- **비즈니스 규칙은 도메인에서.** 확인 없이 지어내지 말고, 모르면 "확인 필요"로 두고 형식·무결성부터 확정한다.
- **커버리지 매트릭스로 누락을 드러낸다.** 검증 없는 제약을 명시하는 것이 통합 리뷰와 보강의 지도다.
