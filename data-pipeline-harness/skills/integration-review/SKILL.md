# Integration Review — 설계 정합성 검증

네 전문가의 산출물이 **하나의 일관된 파이프라인**을 가리키는지 검증한다. 개별 산출물의 우수함이 아니라 **경계면의 정합성**이 목적이다. 이 단계가 "네 개의 설계 문서"를 "실행 가능한 하나의 파이프라인"으로 바꾼다.

## 검증 절차

### 1. 카탈로그를 기준축으로 고정한다
`01_schema.md`의 엔티티/필드 카탈로그(E번호·필드 ID)가 유일한 대조축이다. ETL·검증·모니터링이 같은 필드 ID를 일관되게 참조하는지 본다. 색인이 없으면 대조 불가 — schema-designer에게 색인을 요청한다.

### 2. 경계면별로 교차 비교한다
"존재 확인"이 아니라 **양쪽을 나란히 놓고 대조**한다:

**스키마 ↔ ETL**
- 카탈로그의 모든 타겟 필드를 ETL이 채우는가? (미충족 = 누락)
- NOT NULL 필드를 ETL이 보장하거나 기본값이 있는가?
- ETL 병합 키 = 카탈로그 PK? (불일치 = 멱등성 깨짐)
- ETL이 채우는 필드가 전부 카탈로그에 존재? (고아 필드 = 불일치)
- ETL 변환 결과 타입이 카탈로그 타입과 호환?

**스키마 ↔ 검증**
- 카탈로그의 모든 제약(NOT NULL·CHECK·UNIQUE·FK)에 대응 규칙이 있는가? (제약 있고 규칙 없음 = 누락)
- 검증 규칙의 필드 ID가 카탈로그에 실재하는가?

**ETL ↔ 검증**
- ETL의 데이터 손실·형변환 지점(NULL→0)에 검증이 있는가?
- block 규칙이 ETL 재처리 전략과 모순되지 않는가?

**검증 ↔ 모니터링**
- 모든 block 규칙에 대응 알림(page)이 있는가? (block인데 감시 없음 = 위험)
- 모니터링 심각도 매핑이 검증 심각도와 일치하는가?

**스키마/ETL ↔ 모니터링**
- 핵심 엔티티(팩트·마트)마다 신선도·양 지표가 있는가? (없음 = 누락)
- 모니터링이 요구하는 계측을 ETL이 남기는가? (안 남김 = 감시 불가)

**스펙 ↔ 전체**
- `00_spec.md`의 SLA가 모니터링 SLO로 커버되는가?
- 스펙이 설계하라던 엔티티가 전부 카탈로그에 있는가?

### 3. 분류한다

| 분류 | 조건 | 처리 |
|------|------|------|
| **정합(Consistent)** | 경계면이 카탈로그 기준으로 일치 | 통과 |
| **불일치(Mismatch)** | 양쪽이 다른 것을 가리킴(키·타입·필드 ID) | 담당자 조정 |
| **누락(Gap)** | 있어야 할 대응물 부재(미충족 필드·검증 없는 제약·감시 없는 엔티티) | 담당자 보강 |
| **위험(Risk)** | 이어지나 운영상 위험(block 규칙 감시 없음·멱등성 취약·알림 과다) | 아키텍트 판단 |

### 4. 보강 지도를 만든다
각 발견을 담당 전문가와 참조 ID(필드/규칙)로 태깅한다. 이 태깅이 아키텍트의 재위임 트리거다. 무엇이 안 맞는지 정확히 지목하는 것이 곧 보강의 지도다.

## 출력 형식

`data-pipeline/_workspace/05_review.md` (감독자가 전달한 정확한 경로 사용):

```markdown
# 통합 정합성 검토
> 검토시점: {YYYY-MM-DD} | 회차: {N}

## 경계면 정합성 매트릭스
| 경계면 | 점검 항목 | 결과 | 근거(ID) |
|--------|----------|------|----------|
| 스키마↔ETL | E1 전 필드 충족 | 정합 | E1.* |
| 스키마↔ETL | E2.segment 충족 | 누락 | ETL 미채움 |
| 검증↔모니터링 | V1(block) 알림 | 위험 | 감시 없음 |

## 불일치·누락·위험 목록 (담당자·우선순위 태깅)
- [누락/etl] E2.segment 미충족 → etl-engineer, 우선 상
- [누락/validation] E2.email UNIQUE 검증 없음 → validation-engineer
- [위험/monitoring] V1 block 규칙 감시 없음 → monitoring-engineer

## 정합 확인 항목
- {통과한 경계면 요약}

## 미해결 (보강 한도 초과 시)
- {구조적으로 해소 불가한 항목 + 사유}
```

## 핵심 원칙

- **개별 검증이 아니라 경계면 대조다.** 네 파일을 필드 ID로 정렬해 동시에 본다.
- **카탈로그가 기준축이다.** 색인 없이는 대조 불가. 없으면 스키마에 되돌린다.
- **누락 발견이 절반의 일이다.** 무엇이 안 이어지는지가 곧 보강의 지도이자 설계의 정직한 한계다.
- **모순은 판정하지 말고 병기한다.** 두 산출물이 근본 충돌하면 봉합하지 말고 아키텍트 결정에 남긴다.
- **입력 누락 시 정합으로 처리하지 않는다.** 빠진 산출물이 있는 경계면은 "검증 불가"로 표시한다.
