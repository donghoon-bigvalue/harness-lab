# Monitoring Setup — 파이프라인 관측성 설계

파이프라인이 운영 중 살아 있고 건강한지 감시하는 체계를 설계한다. 설계가 아무리 좋아도 조용히 실패하면 나쁜 데이터가 하류로 흘러간다. 목표는 지표 나열이 아니라, **ETL 스테이지·검증 규칙에 연결되고 SLA가 임계값으로 번역된 알림 체계**다.

## 설계 절차

### 1. 감시 대상을 ETL·검증에서 가져온다
지어낸 지표가 아니라, `02_etl.md`의 스테이지 경계(추출·변환·적재 완료)와 `03_validation.md`의 규칙 위반이 감시의 실체다. 핵심 엔티티(팩트·마트)와 block 규칙을 먼저 목록화한다.

### 2. 다섯 축으로 지표를 도출한다
- **신선도(freshness)**: 마지막 적재 시각, SLA 시한 내 완료 여부. *가장 중요* — 데이터가 늦으면 하류가 옛것을 본다
- **양(volume/row-count)**: 처리 행 수, 전일/기대 대비 편차. 0건·급감·급증은 조용한 실패 신호
- **품질(quality)**: 검증 실패율, 격리 건수(검증 규칙과 직결)
- **지연(latency)**: 스테이지별·end-to-end 소요 시간, SLA 대비
- **스키마 드리프트**: 원천 컬럼 추가/삭제/타입 변경(특히 CDC·반정형 원천)

### 3. SLA를 SLO·임계값으로 번역한다
"신선해야 한다"는 감시 불가. `00_spec.md`의 SLA를 구체적 숫자·시각으로 옮긴다:
- 신선도: "적재 완료 ≤ 매일 07:00, 초과 시 알림"
- 양: "행 수 전일 대비 ±30% 이탈 시 알림"
- 지연: "end-to-end < 2h"

### 4. 알림 라우팅·심각도를 매핑한다
검증 심각도와 일치시킨다 — 어긋나면 사소한 일에 깨거나 치명적 실패를 놓친다:
- block 규칙 위반 / 신선도 SLA 초과 → **page**(즉시 on-call)
- warn 규칙 위반 / 경미한 편차 → **notify**(비동기 채널)
- 정보성 → **log/대시보드**
- 채널·수신자 지정(미정이면 심각도만 확정하고 채널은 "미정" 표기)
- **알림 피로 경계**: 진짜 대응이 필요한 것만 page. 노이즈는 알림을 죽인다

### 5. 계측 가능성을 확인한다
지표가 실측되려면 ETL이 계측(완료 타임스탬프·행 수)을 남겨야 한다. 없으면 etl-engineer에게 계측 추가를 요청하고, 불가하면 감시 공백으로 명시한다.

## 출력 형식

`data-pipeline/_workspace/04_monitoring.md` (감독자가 전달한 정확한 경로 사용):

```markdown
# 모니터링·관측성 설계
> 설계시점: {YYYY-MM-DD}

## M1. {지표명} [E1 | 스테이지: load]
- 유형: 신선도 | 양 | 품질 | 지연 | 스키마 드리프트
- 대상: E1 적재 완료 시각 / V1 위반율 / ...
- SLO·임계값: 신선도 ≤ 07:00 AND < 6h; 행 수 전일 ±30%
- 알림: page(on-call) | notify(#data-alerts) | log
- 심각도 매핑: V1(block) 위반 → page / V4(warn) → notify
- 연결: 검증 V1, ETL 스테이지 load

## SLO 요약표
| SLA(스펙) | SLO·임계값 | 대상 | 알림 |
|-----------|-----------|------|------|

## 알림 라우팅표
| 조건 | 심각도 | 채널 | 수신자 |
|------|--------|------|--------|

## 헬스 대시보드 구성
- 한눈 지표 묶음(엔티티별 신선도·행수·실패율)

## 커버리지
- 핵심 엔티티별 신선도·양 지표 유무
- block 규칙별 알림 매핑 유무 (누락 = 위험)
- 계측 불가로 감시 못 하는 지점
```

## 핵심 원칙

- **감시 대상은 ETL·검증에서 나온다.** 지어낸 지표가 아니라 스테이지 경계·규칙 위반이 실체다. 핵심 엔티티에 신선도·양이 없으면 통합 리뷰에서 누락으로 걸린다.
- **SLA를 임계값으로 번역한다.** 숫자·시각이 아니면 감시할 수 없다.
- **심각도를 검증과 일치시킨다.** block→page, warn→notify. 어긋나면 대응이 무너진다.
- **조용한 실패를 잡는다.** 성공으로 끝났는데 0건·옛날치·전부 NULL이 가장 위험하다. 양·신선도·분포를 감시한다.
- **알림 피로를 경계한다.** 전부 page면 아무도 안 본다. 대응 필요한 것만 page.
