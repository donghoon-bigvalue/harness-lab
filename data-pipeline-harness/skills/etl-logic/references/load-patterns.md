# 적재 방식(Load Pattern) 선택 기준

ETL 적재 방식은 그레인·주기·규모·갱신 특성에서 결정된다. 근거 없이 전체 갱신을 남발하면 비용·시간이 폭발하고, 무분별한 append는 중복을 낳는다. 아래 분기로 고른다.

## 목차
1. 선택 결정 트리
2. 방식별 상세
3. 멱등성 보장 패턴
4. 특수 상황(SCD, late-arriving, 백필)

## 1. 선택 결정 트리

```
레코드가 적재 후 갱신되는가?
├─ 아니오 (불변 이벤트/로그) ──────────→ 증분 append
└─ 예 (갱신됨)
     ├─ 삭제 추적·낮은 지연 필요? ─ 예 → CDC
     └─ 아니오
          ├─ 데이터 규모 작음(수만 행) & 이력 불필요 → 전체 갱신(full refresh)
          └─ 규모 큼 or 이력 필요 → 병합(merge/upsert)
```

## 2. 방식별 상세

### 전체 갱신 (Full Refresh)
- **언제**: 소규모 디멘전·룩업, 원천 전체를 매번 다시 계산해도 싼 경우
- **방법**: 대상 테이블 truncate 후 전량 재적재 (또는 원자적 swap)
- **장점**: 단순, 멱등(항상 최신 전량)
- **단점**: 규모 커지면 비용·시간 폭발, 이력 없음
- **주의**: 원자적 교체(임시 테이블 빌드 후 rename)로 조회 중단 방지

### 증분 Append
- **언제**: 불변 이벤트/로그(클릭, 거래, 센서). 갱신되지 않는 데이터
- **방법**: 워터마크(마지막 처리 시각/시퀀스) 이후만 추출해 추가
- **멱등성 위험**: 재실행 시 같은 구간을 두 번 넣으면 중복. → 실행 전 대상 파티션 삭제 후 재적재(delete-then-insert), 또는 적재 키로 dedup
- **주의**: late-arriving(워터마크보다 늦게 도착한 과거 데이터) 누락 위험 → 워터마크에 여유(lookback window) 둠

### 병합 (Merge / Upsert)
- **언제**: 갱신되는 레코드(주문 상태 변경, 프로필 수정). 대부분의 마트·디멘전
- **방법**: 비즈니스 키(= 카탈로그 PK)로 MATCH → 있으면 UPDATE, 없으면 INSERT
- **멱등성**: 키가 정확하면 몇 번 돌려도 같은 결과 (권장 기본값)
- **주의**: 병합 키가 카탈로그 PK와 반드시 일치해야 함. 불일치 시 중복 행 발생

### CDC (Change Data Capture)
- **언제**: 낮은 지연, 삭제 추적, 원천 부하 최소화 필요
- **방법**: 원천 트랜잭션 로그(binlog/WAL) 기반 insert/update/delete 스트림 소비
- **멱등성**: 이벤트에 LSN/오프셋 순서 보장, 중복 이벤트는 키+버전으로 dedup
- **주의**: 스키마 드리프트에 취약 → 모니터링에 드리프트 감시 필수

## 3. 멱등성 보장 패턴

재실행해도 결과가 같아야 파이프라인이다. 방식별 핵심:

| 방식 | 멱등성 장치 |
|------|------------|
| 전체 갱신 | 항상 전량 교체 → 본질적으로 멱등 |
| 증분 append | delete-then-insert(대상 파티션 선삭제) 또는 적재 키 dedup |
| 병합 | 비즈니스 키(=PK) 기반 upsert |
| CDC | 오프셋 순서 + 키+버전 dedup |

**안티패턴**: 워터마크 없는 순수 append(`INSERT ... SELECT ... WHERE created_at > 어제`를 시각 겹치게 재실행) → 중복. 반드시 경계를 결정적으로 만든다.

## 4. 특수 상황

### SCD (Slowly Changing Dimension)
갱신되는 디멘전의 이력 관리:
- **Type 1**: 덮어쓰기(이력 없음) — 병합 update
- **Type 2**: 변경 시 새 행 + 유효기간(valid_from/valid_to, is_current) — 이력 보존. 카탈로그에 유효기간 필드가 있어야 함

### Late-arriving 데이터
워터마크보다 늦게 도착한 과거 데이터:
- lookback window(예: 최근 3일 재처리)로 흡수
- 또는 도착 시각 기준 파티션 + 주기적 재계산

### 백필 (Backfill)
과거 구간 재적재:
- 파티션 단위로 재처리 가능하게 설계(파티션이 재처리의 단위)
- 멱등 방식이면 백필이 안전(병합·delete-then-insert)
